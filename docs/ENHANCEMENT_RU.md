# Локальное улучшение фото — 30.09.2026

## Выбор

Для небольших фотографий используются ESRGAN Slim 2×, 3× и 4× через UpscalerJS 1.0.0
и TensorFlow.js 4.11.0. Slim рассчитан на более лёгкое увеличение; вариант 2× выбран
по умолчанию, чтобы ограничить затраты памяти и время относительно 4×.
С версии 1.2.0 пользователь выбирает множитель рядом с галочкой улучшения.
Для каждого множителя поставляются собственные веса; одновременно загружена
одна модель, а при смене множителя предыдущая освобождается.
Версия TensorFlow.js соответствует peer dependency UpscalerJS.
Модель, веса и исполняемый код поставляются внутри расширения Manifest V3.

Источники:
- https://upscalerjs.com/models/available/upscaling/esrgan-slim/
- https://upscalerjs.com/documentation/guides/browser/models/
- https://upscalerjs.com/documentation/api/upscale/

Увеличение и исправление экспозиции — разные задачи. Модель увеличивает изображение;
отдельная умеренная тоновая кривая анализирует распределение яркости и корректирует
его без независимого растягивания цветовых каналов. Полностью выбитые света не
восстанавливаются. Тесты сравнивают светлые, тёмные и обычные изображения, сохраняют
прозрачность и крайние значения чёрного/белого.

## Исполнение

Content script управляет просмотром. Service worker проверяет отправителя, адрес
снимка и соответствие текущей задаче, затем передаёт работу offscreen-документу.
Там доступны Canvas и WebGL, а доступ к изображениям обеспечивают ограниченные
host permissions. Обработка внутри самой страницы упиралась бы в CORS и её CSP.

- https://developer.chrome.com/docs/extensions/develop/concepts/network-requests
- https://developer.chrome.com/docs/extensions/reference/api/offscreen

Пользователь видит оригинал сразу, улучшение появляется после готовности.
Галочка включена по умолчанию; её состояние сохраняется до перезагрузки вкладки.
Выключение, перелистывание и выход отменяют текущую задачу. Идентификаторы запросов
не позволяют результату старого фото заменить новое. Масштаб и положение задаются
по оригиналу, поэтому переключение не сдвигает изображение.

ИИ обрабатывает снимки до 0,9 Мп и 1400 пикселей по длинной стороне частями по 64
пикселя с перекрытием. Выход ИИ ограничен 12 Мп; при ×4 это допускает исходник
до 0,75 Мп. Большие фото получают только тоновую коррекцию с пояснением в статусе. Ограничения
обработчика: 12 Мп, 20 МБ, 90 секунд на задачу, очередь максимум четырёх вкладок.
Скрытый документ использует таймер для уступания потока между частями: ожидать
визуальный кадр в невидимом документе ненадёжно. Модель освобождается после минуты
простоя. Нет отправки фото на сервер и удалённого исполняемого кода.

## Проверено

Chrome 154.0.8037.58, отдельный временный профиль, настоящий unpacked manifest.
Локальная модель действительно выполняется в offscreen-документе; синтетическое
192×128 PNG превращается в 384×256, 576×384 и 768×512 соответствующими моделями.
Проверены смена множителя, быстрые переключения во время обработки, выбор при
выключенном улучшении и сохранение масштаба просмотра.
Проверены строгие CSP/Trusted Types, отсутствие
разрешения на `data:`-изображения у страницы, переключение оригинал/результат,
отмена обработки и отсутствие скачивания модели из CDN.

В headless-тесте используется программный WebGL для воспроизводимости. Этот тест
подтверждает цепочку исполнения, но не оценивает качество конкретных фотографий
пользователя и скорость его видеокарты. Рабочий профиль Chrome не затрагивался.
Исходный полноэкранный просмотр уже проверен пользователем на живом альбоме;
визуальная оценка нового улучшения остаётся за пользователем.
